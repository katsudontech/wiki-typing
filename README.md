# WikiTyping

> Wikipediaの記事をタイピング教材として利用し、タイピング練習と知識のインプットを同時に行えるWebアプリです。興味のあるテーマを指定することで、その分野について学びながらタイピングを練習できます。

**デモ:** [https://wiki-typing.katsudon.app](https://wiki-typing.katsudon.app)  
**ステータス:** 公開中  
**開発期間:** 2026年3月〜2026年6月  
**開発体制:** 個人開発


## 概要

### 解決したかった課題

寿司打やe-typingなどの既存のタイピングサービスでは、あらかじめ用意された文章を使って練習するため、タイピング技術は身につく一方で、入力する内容から新しい知識を得られる機会は限られています。また、同じような文章を繰り返し入力することで、練習が単調に感じられることもありました。

そこで、タイピング練習に使う時間を知識のインプットにも活用し、タイピングしながら興味のある分野について学べる体験を作りたいと考えました。

### 解決方法

Wikipedia APIからランダムな記事、または利用者が指定したキーワードに関連する記事を取得し、その内容をGemini APIでタイピング教材に適した長さへ要約します。

さらに、生成した文章をタイピング画面で扱いやすい形式に整形することで、Wikipediaの記事について学びながらタイピングを練習できるようにしました。毎回異なる記事を教材として利用できるため、新しい知識との出会いと、飽きにくいタイピング練習の両立を目指しています。

## 主な機能

- **Wikipedia記事からのお題生成**\
  Wikipedia APIからランダムに記事を取得し、タイピングのお題を生成します。

- **キーワードによる記事検索**\
  歴史やコンピュータなどのキーワードを指定すると、関連する検索結果から記事を選択できます。未指定の場合はランダムな記事が選ばれます。

- **生成AIによる教材への変換**\
  Wikipediaの記事をGemini APIで指定した長さに要約し、本文と読み方を文節単位に分割したデータへ変換します。

- **入力位置のリアルタイム表示**\
  入力済み・入力中・未入力の部分を色分けして表示します。長い文章では入力中の位置まで自動でスクロールします。

- **難易度設定**\
  お題の最大文字数と、出題してほしい記事のキーワードを設定できます。設定内容はブラウザに保存されます。

- **スコアと履歴の記録**\
  KPM、正確率、入力時間、e-typing形式のスコアを計算し、プレイ履歴としてブラウザに保存します。KPMとスコアの推移はグラフで確認でき、履歴から出題元のWikipedia記事を開くこともできます。

## 技術的な工夫・苦労した点

### 1. タイピング画面から逆算した生成データの設計

**課題:**\
当初は、Gemini APIから漢字交じりの文章と読み方を、それぞれ一つの文字列として受け取っていました。しかし、この形式では、利用者が現在入力している部分と、画面に表示している文章の位置を対応させることが難しくなりました。

**対応:**\
Gemini APIに出力例を含むプロンプトを与え、文章を次のような文節単位のJSON配列として返すように設計しました。

```json
{
  "segments": [
    { "text": "吾輩", "reading": "わがはい" },
    { "text": "は", "reading": "は" },
    { "text": "猫", "reading": "ねこ" },
    { "text": "である", "reading": "である" },
    { "text": "。", "reading": "" }
  ]
}
```

句読点やかぎ括弧など、タイピングの対象にしない記号には空の読み方を設定するルールもプロンプトに含めています。取得後は、各要素を結合したデータをタイピング判定に使用しながら、文節情報を画面表示用として保持します。

**結果:**\
入力済み・入力中・未入力の文節を判定し、元の文章上で現在入力している位置をリアルタイムに強調表示できるようになりました。

### 2. タイピング状態とReactの画面表示の同期

**課題:**\
タイピング判定ライブラリは、キーを入力するたびにオブジェクト内部の状態を書き換えます。しかし、オブジェクト内部の値が変わるだけではReactによる再レンダリングが発生せず、入力結果が画面へ反映されない問題がありました。

**対応:**\
タイピング判定用のオブジェクトとは別に、入力済みの文章や残りの文章をReactのstateとして管理しました。キー入力の判定後にライブラリの状態をstateへ同期し、毎回確実に画面を更新するようにしています。

また、キーの長押しによる連続入力や判定対象外のキーを除外し、ゲーム開始後の最初の有効な入力から計測を開始するようにしました。

**結果:**\
キー入力のたびに進捗が正しく反映され、ミス数、進捗、ハイライト、スコア計算を一貫して管理できるようになりました。

### 3. 複数の外部APIを利用する処理のエラー対応

**課題:**\
お題を生成するには、Wikipedia APIによる記事の検索・取得と、Gemini APIによる要約・整形を順番に実行する必要があります。そのため、通信エラー、記事本文の不足、生成結果の形式不備など、複数の段階で処理に失敗する可能性がありました。

**対応:**\
Wikipedia APIの各レスポンスステータスを確認し、本文が短すぎる場合やGemini APIの出力からJSONを取得できない場合もエラーとして処理しています。

非常に長い記事をそのままGemini APIへ渡さないよう、入力するWikipedia本文を最大20,000文字に制限しました。処理に失敗した場合はアプリ全体を停止させず、エラー画面と再試行ボタンを表示します。

**結果:**\
一時的なAPIエラーや想定外の生成結果が発生しても、利用者が画面上からお題の生成をやり直せるようになりました。

## 品質・セキュリティ

### 品質

- TypeScriptのstrictモードを有効にしています。
- Next.jsのCore Web Vitalsルールを含むESLint設定を使用しています。
- Wikipedia APIのレスポンスステータスや取得した本文の長さを確認しています。
- Gemini APIの生成結果からJSONを抽出できない場合は、エラーとして処理しています。
- 外部APIの動作、Gemini APIの出力形式、タイピングライブラリの初期化を確認するための動作確認用スクリプトを作成しました。
- Vercelへのデプロイ時にNext.jsの本番ビルドを実行しています。

### セキュリティ

- Gemini APIキーはサーバー側の環境変数として管理し、ブラウザへ公開していません。
- Wikipedia検索に使用するキーワードは、`encodeURIComponent`でエンコードしてからAPIへ渡しています。
- Gemini APIへ渡すWikipedia本文を最大20,000文字に制限しています。
- 外部サイトへのリンクには`noopener noreferrer`を設定しています。
- アカウントや個人情報を扱わないため認証機能は導入せず、設定と履歴は利用者のブラウザ内に保存しています。

## ローカルでの起動方法

### 必要な環境

- Node.js 20.9以上
- npm
- Gemini APIキー

### セットアップ

リポジトリを複製し、依存パッケージをインストールします。

```bash
git clone https://github.com/katsudontech/wiki-typing.git
cd wiki-typing
npm install
```

プロジェクト直下に`.env.local`を作成し、Gemini APIキーを設定します。

```env
GEMINI_API_KEY=
```

開発サーバーを起動します。

```bash
npm run dev
```

ブラウザで[http://localhost:3000](http://localhost:3000)を開きます。

### 確認コマンド

```bash
npm run lint
npx tsc --noEmit
npm run build
```

## 制約・今後の改善

### 現在の制約

- ゲームを開始するたびにWikipedia APIとGemini APIを呼び出すため、お題が表示されるまで待ち時間が発生します。
- 生成AIの出力には揺らぎがあり、文章の要約や読み方が常に正確であるとは限りません。
- 設定とプレイ履歴はブラウザのlocalStorageに保存しているため、別の端末やブラウザとは共有できません。
- プレイ履歴をクラウドに保存する機能や、利用者間のランキング機能はありません。
- 自動テストとGitHub ActionsによるCIは未導入です。
